# Provenance and dependency report

Where every declaration in this Lean development comes from, what depends on
what, and how much of each item's support comes from which source.

Generated by `tools/provenance.py` from the Lean sources and from the compiled
kernel environment (`tools/DepDump.lean`).  Companion figures:
`docs/status/dashi.svg` (the DASHI provenance infographic) and
`docs/status/dependencies.svg` (the dependency graph).

## 0. How a declaration is attributed

| source | rule |
| --- | --- |
| **DASHI Agda bridge (PR #555 / #581 / #582)** | the declaration is named in an upstream correspondence row of `PORTING_NOTES.md` or of `RELATED_WORK.md` §1 — i.e. the notes state that it renders an idea of the bridge |
| **Wikidata data model & standards** | not DASHI-traced, lives in a Wikidata data-model module, and states Wikidata vocabulary (item/property ids, rank, truthy, statements, RDF, constraints, identifiers, provenance) |
| **Original to this Lean port** | everything else: the executable engines, their exactness theorems, the generic epistemic machinery and the countermodels |

"Declarations" here are the named top-level declarations of the sources
(`theorem`, `lemma`, `def`, `abbrev`, `structure`, `inductive`, named `instance`);
anonymous instances and the auxiliary constants the compiler generates are not
counted as items, though they are followed through when computing dependencies.

The attribution is *auditable*: each DASHI row in §5 below carries the upstream idea
it was traced to, and the in-source `-- @source` comments carry the same text next to
the declaration itself.
