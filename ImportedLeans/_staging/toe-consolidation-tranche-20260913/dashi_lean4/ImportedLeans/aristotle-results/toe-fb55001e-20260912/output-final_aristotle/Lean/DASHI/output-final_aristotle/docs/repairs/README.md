# Proposed repairs

Generated by `scripts/make-repairs.sh`, which runs `wikidata repairs` over the bases listed in it.  For every flagged issue the tool proposes the changes that would fix it, with the reason for each, and marks the ones a check certifies: a `proven` candidate removes the issue it is raised for, adds no error and no warning the base did not already carry, and lowers the repair debt.  A `rejected` candidate is not wrong — it is a choice for an editor to make.

**Nothing here has been applied.**  The input files are untouched; `NAME-repaired.wdkb` is the base the recommended changes would produce, written out only so the two can be compared.

Each review comes in three forms: `NAME.csv` (one line per candidate repair, for a spreadsheet), `NAME.html` (a page with the summary on top) and `NAME.txt` (a plain text review to paste onto a talk page).  How the workflow works and what is proved about it is in [../REPAIRS.md](../REPAIRS.md).
